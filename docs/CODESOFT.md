Codesoft TP-3260VL connects by USB to the iMin terminal. This application implements a WebUSB ESC/POS adapter for Android Chrome; the Codesoft Windows installer is unnecessary for this connection. The manufacturer's [product page](https://code-soft.co.th/product/47-TP-3260VL) identifies USB and ESC/POS support. The existing [iMin SDK](https://oss-sg.imin.sg/docs/en/Printer.html) targets its built-in printer, so external Codesoft printing uses a separate USB transport.

Open the HTTPS POS in Chrome on the iMin, connect and power the Codesoft, then open **Settings → POS devices → Codesoft TP-3260VL → Connect Codesoft USB**. Select the Codesoft device and grant the browser and Android USB permission. This association belongs to the selected POS terminal and browser; receipts never auto-select other authorized USB devices. Leave printing mode as iMin to try the built-in printer first, or select Codesoft USB to use it directly. The Codesoft paper option defaults to 80 mm / 576 dots and also supports 58 mm / 384 dots with the printer's paper guide. Save device settings after changing options and use Test Print.

Discovery calls `navigator.usb.getDevices()` and opens only the device explicitly chosen during setup. USB printer-class interfaces use GET_PORT_STATUS to check paper/error/offline flags without printing; supported vendor-specific bulk interfaces can confirm the USB connection but do not expose printer-class hardware status. A disconnect requires reconnecting and may prompt again for Android USB access. Chrome's [WebUSB documentation](https://developer.chrome.com/docs/capabilities/usb) describes the Android permission flow. If the iMin browser/WebView does not expose WebUSB, use Chrome; the app reports the missing capability.

Thai text, item columns, logos, barcodes and QR codes are rendered with the existing Sarabun receipt layout, then encoded as monochrome ESC/POS raster commands. Each image stripe stays below the model's documented 8 KB buffer. The [ESC/POS raster command](https://download4.epson.biz/sec_pubs/pos/reference_en/escpos/gs_lv_0.html) is a legacy command used for compatibility with this printer. Cutter and cash-drawer commands honor the saved device controls.

iMin defaults to the built-in SPI connection and works without connecting or pairing Codesoft. In **Settings → POS devices → Printing**, choose **iMin (default)** or **Codesoft TP-3260VL (USB)** and save the device. Selecting iMin restores SPI and the browser fallback; the connection remains editable for iMin models that require USB or Bluetooth. Codesoft setup controls appear when it is selected as the primary printer or explicitly enabled as a backup.

Only absent/disconnected iMin discovery triggers fallback. By default the browser print window opens. To check an authorized, connected Codesoft first, explicitly select **When iMin is unavailable → Codesoft USB backup** and save. Previously paired USB devices alone do not enable this backup. Paper-out/head-open faults on a connected printer remain recoverable errors. Once receipt commands begin, failures never switch printers automatically, because some paper may already have printed. A USB success means all transfers were accepted and the available port status checks passed; physical output must be tested on the real hardware.

The drawer can stay plugged into the iMin when Codesoft prints receipts. Set **Drawer connected to → iMin device** in POS device settings, enable the drawer and save. Cash bills then use iMin's separate [openCashBox API](https://oss-sg.imin.sg/docs/en/JSPrinterSDK.html), without checking the built-in printer's paper or printer status. The iMin service still needs to be reachable. **Test open drawer** sends only a drawer command, without printing a receipt or recording a sale. QR payments and reports do not trigger automatic opening. If the iMin drawer service fails after Codesoft prints, the print job remains printed and the error explicitly says the receipt already printed and directs the operator to retry only the drawer.
