# CIDA POS architecture

The cashier and back-office application now uses Cloudflare Workers, D1 and private R2. The prior PostgreSQL deployment is retained in Git history and the legacy reference directories for rollback.

Next.js App Router / strict TypeScript provides Thai cashier and back-office interfaces. Cloudflare D1 stores normalized sales, immutable item snapshots, payments, receipt jobs, audited configuration and financial closes. All amounts are integer satang. An optimistic revision assertion and all staged mutations commit in one native D1 batch. A conflict rolls back the complete batch and retries against a fresh revision; read-only operations also verify their revision before returning. Database triggers protect immutable records and monetary constraints. Checkout keys are unique, payload-bound and safe to retry after lost responses. No offline financial acceptance.

Opaque, hashed database sessions use HttpOnly SameSite cookies, bcrypt passwords, server permissions and same-origin mutation checks. Catalog/cart updates stay local. Checkout is recalculated on the server. Product, category and price edits never change historical item snapshots.

Bangkok business dates use configured opening time and cover opening <= time < next opening. Reports, category tables, CSV exports and 58 mm daily printouts use full-day totals without timed periods. Legacy cutoff fields are ignored when reading saved configuration. Creating round snapshots is retired; historical snapshot rows and their immutability protections are retained. Closing freezes the day's ledger, including void/refund operations. Corrections require reopening with a reason and preserve prior close revisions.

Printing has a durable outbox. A committed sale returns its receipt immediately; independent claim/report APIs record printer outcomes. Reprinting only creates a new print job. A browser reload exposes unconfirmed jobs for explicit recovery because physical exactly-once printing cannot be guaranteed after power loss. iMin SDK calls are confined to an adapter. iMin discovery/connection failures automatically open the computer receipt-print dialog before any receipt content is sent, with a visible fallback notice and mandatory operator confirmation. Mock printing remains an explicit alternative. Failures after print commands begin stay recoverable without an automatic duplicate.

The cashier report lives in the POS modal and prints a compact 58 mm category/amount summary through the same durable outbox. It omits payment, quantity and adjustment detail while retaining their effect on net totals. Back-office reports print a standalone A4 document via a portal; named print-page rules isolate it from the navigation and charts, repeat table headers and add page numbers. Selected date ranges/filters and the data timestamp identify the printed scope. Stale asynchronous responses cannot replace a newer report selection. The dashboard reads 7/30-day daily points and the selected day's report in one revision-checked D1 operation, honoring each saved business day's opening time and subtracting refunds without counting voided orders.

Deployment: Cloudflare Workers using the OpenNext adapter, native D1 and private R2 bindings. Local development uses Wrangler emulators. R2 objects hold media and complete reset archives; D1 retains authenticated download metadata and SHA-256 checksums. Archive storage is verified before a guarded reset batch can delete the ledger. PostgreSQL export/import helpers retain IDs, account hashes, audit history, counters and existing reset archives. iMin browser requires the manufacturer's matching local SDK/plugin. Actual model, firmware, Android version, print width, cutter, drawer and Thai shaping must be verified on hardware. Kitchen routing is configurable; network printer transport requires a supplied bridge and is disabled until configured.
